## 1. One-liner

**CrewGit is the git-native collaboration layer for coding agents.** Every agent gets a task contract,
an isolated worktree, a quality gate, and a provenance trail. Every handoff is a commit you can
review, revert, replay, and blame.

Tagline: *Agents write code. Git keeps them honest.*

## 2. Problem

A solo developer today can run four coding agents at once (Claude Code, Codex, Gemini CLI, Aider, or
a local model). Collaboration between them is still manual, and it fails in three predictable ways:

1. **Merge hell.** Two agents edit the same file in parallel; the second run silently overwrites the
   first, or produces a conflict nobody can attribute.
2. **Unreviewable output.** Agents return chat logs and a dirty working tree. There is no diff
   boundary, no declared scope, no evidence that tests ran, and no way to tell which agent produced
   which line six weeks later.
3. **Unsafe automation.** "Just let it commit" means an agent can touch migrations, CI config, or
   secrets in the same run that it "fixes a typo". Reviewers react by not using agents for anything
   important.

Orchestration frameworks (LangGraph, CrewAI, AutoGen, OpenAI Agents SDK) solve *control flow inside
one runtime*: nodes, edges, state, retries. They do not solve *collaboration between independent
agents over one repository*: ownership, isolation, review, provenance, and rollback. Git solved
exactly that problem for humans decades ago. Agents are just faster, more literal contributors.

## 3. Users and jobs

| User | Job to be done | Success looks like |
|---|---|---|
| Solo dev running 2–5 CLI agents | Ship several small tasks in parallel without merge chaos | 3 tasks land in one afternoon, zero manual conflict resolution |
| Small team (2–6 devs) | Let agents do the mechanical work, humans review | Every AI change arrives as a reviewable branch with green gates |
| OSS maintainer | Triage AI-generated PRs | Scope violations and untested claims are rejected before human review |
| Framework builder | Add a collaboration substrate under their own orchestrator | Adapter + MCP server, no rewrite |

## 4. Product principles

1. **Git is the bus.** State lives in commits, branches, worktrees and notes — not in a proprietary
   database. Uninstall CrewGit and you still have a normal repository.
2. **Contract before code.** Agents declare what they will touch and how success is measured, before
   they touch anything.
3. **Gates over trust.** Scope, budget, lint, tests, review, human — in that order, fail-fast.
4. **Provenance by default.** If a merge cannot be traced to a prompt and a run, it is not done.
5. **Works with any agent.** CLI adapters and an MCP server; no vendor lock-in, no API key required
   for the demo.

## 5. User stories (P0)

| ID | Story | Acceptance criteria |
|---|---|---|
| US-01 | As a solo dev, I run three independent tasks in parallel and merge them cleanly | `crewgit run --ready --parallel 3` completes; no two concurrent runs share a scope glob; all three merge into `main`; `pytest` green on `main` |
| US-02 | As a reviewer, I am protected from out-of-scope edits | A run that edits a file outside its contract `scope` fails the `scope` gate, is never mergeable, and the manifest lists the offending paths |
| US-03 | As a reviewer, I get a machine-readable verdict from a review agent | Review gate stores `{"verdict":"revise","notes":[...]}`; unparseable output becomes `needs_human`, never auto-approve |
| US-04 | As a future maintainer, I can trace any merged line back to its agent and prompt | `git log --show-notes=crewgit` shows the manifest for every run commit; merge commit carries `Crewgit-Task/Run/Agent/Contract-Hash` trailers |
| US-05 | As a sceptic, I can test whether an agent run is reproducible | `crewgit replay <run>` either reports identical diff hash or lists diverged files; never claims success from exit code alone |
| US-06 | As a user of another agent, I can join without a plugin | A `generic` adapter runs any CLI via a command template; an MCP stdio server exposes `crewgit_list_tasks`, `crewgit_get_task`, `crewgit_submit_run`, `crewgit_get_board` |
| US-07 | As a first-time visitor, I see the value in under 90 seconds, offline | `crewgit demo` builds a toy repo, runs planner → coder → reviewer, blocks one scope violation, retries, merges, and prints a board summary — with no API keys |
| US-08 | As a cost owner, I know what each agent costs | `crewgit stats` aggregates tokens/cost per task and agent from manifests; unknown usage is shown as `unmetered`, never as `0` |
| US-09 | As an owner, I can override a gate deliberately | `crewgit merge --force --reason "..."` records the reason in manifest + commit trailer; override count appears in `stats` |
| US-10 | As a human, I can watch the team without reading logs | `crewgit serve` shows a board: todo / running / review / done / blocked, per-run gate chips, diff stats, cost |

## 6. Functional requirements

| ID | Requirement | Priority | Acceptance |
|---|---|---|---|
| FR-01 | `crewgit init` scaffolds `.crewgit/config.yaml`, `tasks/`, agent registry | P0 | Idempotent; refuses non-git dirs unless `--init-git`; never auto-commits |
| FR-02 | Task contracts as reviewable YAML in `tasks/`, validated on load | P0 | Invalid contract → typed error with field path |
| FR-03 | Dependency-aware scheduling with a ready set | P0 | `depends_on` respected; a task with unmet deps is `blocked` |
| FR-04 | Isolated worktree + branch per run | P0 | Main worktree untouched; branch name `crewgit/<task>/<run>` |
| FR-05 | Pluggable adapters: `mock`, `generic`, `claude` | P0 | Adapter errors surface as failed runs with captured stderr |
| FR-06 | Prompt built from contract + repo context, hashed and stored | P0 | Same contract → same prompt hash |
| FR-07 | Gate pipeline: scope, budget, lint, tests, review | P0 | Fail-fast; each gate stores status + details |
| FR-08 | Run manifest as git note + local JSON | P0 | `crewgit show <run>` works after `git clone` + notes fetch |
| FR-09 | Merge with provenance, fast-forward disabled | P0 | Merge commit has trailers; refuses dirty main |
| FR-10 | File-scope locks with overlap detection | P0 | Overlapping scopes cannot run concurrently; stale locks expire |
| FR-11 | Board API + static web UI | P0 | Polls ≤ 3 s; actions trigger run/merge |
| FR-12 | Replay with diff-hash comparison | P0 | Divergence lists files; mock adapter replays identically |
| FR-13 | Cost ledger and `--json` outputs for scripts | P0 | `stats --json` schema stable |
| FR-14 | MCP stdio server | P1 | Tools list/call over JSON-RPC; usable by Claude Code and other MCP clients |
| FR-15 | GitHub Action that runs gates on a submitted run | P1 | Fails PR when scope/tests fail |
| FR-16 | Hosted read-only board (single binary / docker) | P1 | One container, volume mount, no database required |
| FR-17 | Signed run manifests (per-agent keys) | P2 | Verify signature chain offline |
| FR-18 | Remote runners with cost caps | P2 | Per-run USD cap enforced before merge |
| FR-19 | Multi-repo / monorepo task routing | P2 | Scope can address subdirectories |
| FR-20 | Windows worktree support | P2 | Documented limitations until green in CI |

## 7. Non-functional requirements

- **Performance:** CLI overhead < 2 s per run excluding the agent; board renders 50 tasks < 1 s.
- **Reliability:** a crashed run leaves `main` untouched; `crewgit doctor` detects stale worktrees,
  lock files, and orphan branches; `crewgit gc` cleans them.
- **Security:** environment scrubbed to an allowlist; no secrets in manifests/notes; `--dry-run`
  prints resolved commands; documented trust model (you run agents at your own risk).
- **Compatibility:** macOS + Linux, Python 3.10–3.13, Git ≥ 2.30 (worktrees + notes).
- **Portability:** uninstall leaves a valid git repo with branches and notes intact.

## 8. Non-goals (P0)

- Not an orchestration runtime (no DAG executor replacing LangGraph).
- Not a hosted SaaS, no accounts, no cloud sync.
- Not a model router or a prompt marketplace.
- Not an LLM code reviewer that claims correctness; review gates are advisory and pluggable.
- Not a replacement for human code review.

## 11. Go-to-market (star flywheel)

1. **Asset before ask.** README with a real 60-second transcript, architecture diagram, comparison
   table, and an honest limitations section. People star repos they trust.
2. **One command, no keys.** `pipx install crewgit && crewgit demo`. The demo is the pitch.
3. **Channels, in order:** Show HN (technical framing: "Git is the original multi-agent protocol"),
   r/LocalLLaMA, r/ChatGPTCoding, X thread with GIF, V2EX, 掘金/少数派 Chinese write-up.
4. **Ecosystem pull:** PR to awesome-ai-agents / awesome-mcp lists; publish`crewgit-gate` GitHub
   Action; adapter bounties as `good first issue`.
5. **Content that earns links:** "Why your parallel agents need worktrees, not apologies";
   "Provenance for AI code: trailers, notes, and replay".
6. **Measure and iterate:** track stars/week, installs, demo completions (opt-in telemetry is a
   non-goal; use PyPI + issue volume instead).

## 12. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| "Yet another agent framework" perception | Low stars | Lead with the collaboration gap; show git-native output, not architecture |
| Worktree edge cases (submodules, LFS, hooks) | Broken runs | Detect and warn; document limits; `doctor` command |
| Agent CLIs change flags | Adapter rot | `generic` template as fallback; adapter tests with recorded fixtures |
| Security concern: arbitrary command execution | Trust loss | Explicit agent registration, `--dry-run`, env allowlist, SECURITY.md |
| Scope creep into orchestration | Diluted product | Non-goals list; roadmap gates |
| Demo looks staged | Cynicism | Demo runs real git commands and prints real gate output; mock adapter labelled as such |

## 13. Open questions

1. Should the board be a single static binary (Go/Rust) for zero-dependency install? (P1 decision)
2. Do we need per-agent commit identity (`CrewGit <agent@local>`)? Leaks into git history; decide in
   ADR-7 before P2.
3. Is merge-queue serialization needed once > 5 tasks run concurrently? Measure first.
4. Windows support: Git for Windows worktrees work, but path length and hooks need verification.
